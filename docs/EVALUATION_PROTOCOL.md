# KızılelmAI evaluation protocol

This protocol separates three kinds of labels that must never be pooled into
one reported score.

| Set | Label origin | Permitted use | Not permitted |
| --- | --- | --- | --- |
| Silver training set | The engine's own risk threshold | Weak supervision or exploratory training only | Independent validation, test, or a claim of human annotation |
| Human gold set | Independent annotator decisions, preserved before adjudication | Primary evaluation after the audit passes | Training, threshold selection, or post-hoc label editing |
| External reference benchmark | Published fact-checker verdict and stable source URL | External claim-classification evaluation | Calling it locally human annotated or evidence-grounded RAG evaluation |

## Non-negotiable requirements for a human-gold set

1. Freeze the 500 claim texts and their inclusion/exclusion criteria before
   annotation. Do not select items because the system already got them right or
   wrong.
2. Each item must receive one independent first-round decision from each
   annotator. Preserve the original, time-stamped exports; never overwrite them
   with adjudicated labels.
3. Record annotator IDs, role/training, annotation guide version, date range,
   blinding procedure, conflict-of-interest handling, consent/ethics status,
   and adjudication rule in `annotation_manifest.json`. Keep identities and any
   consent records in a restricted repository; publish pseudonymous IDs only.
4. Report Fleiss' kappa on the first-round decisions, before discussion. Report
   the number of items used in that calculation. Do not calculate IAA from
   adjudicated labels.
5. The final label must be a deterministic majority/adjudication result with an
   audit trail. For factual verdicts, retain a rationale and source URL or
   document identifier for every claim.
6. Before reporting any metric, run:

   ```powershell
   python scripts/audit_evaluation_assets.py --dataset-dir data/gold_500 --strict --output results/gold_500_audit.json
   ```

   A failing audit means the set is not citable as a complete human-gold test
   set. The audit checks internal consistency, not whether people actually
   annotated the data.

## Model and pipeline evaluation

`kizilelma_classifier_v1` is an auxiliary K-6 text classifier. In the current
engine it is **advisory only**: its probability is displayed in the report but
does not enter the retrieval, NLI, or final risk decision. Therefore it must be
evaluated separately from the end-to-end verifier:

```powershell
python scripts/evaluate_k6_on_claims.py `
  --claims data/external_benchmark/facturk_binary_500.csv `
  --output-dir results/facturk_k6_v1
```

For an end-to-end fact-verification result, the test file must contain claims
and fixed evidence documents/URLs that are absent from the retrieval index used
to train or tune the system. Report both answer coverage (`RET` is abstention)
and macro-F1, and retain every claim, retrieved source ID, model version,
threshold, and prediction. A text-only claim label is sufficient for K-6; it is
not sufficient to establish evidence-grounded RAG/NLI performance.

## External benchmark

`scripts/build_facturk_benchmark.py` deterministically samples 250 `true` and
250 `false` claims from the MIT-licensed FACTurk dataset using source verdicts
and URLs. It retains no report content. The dataset should be downloaded from
its official Hugging Face repository and its release revision/hash should be
recorded with a run. This benchmark is external fact-checker supervision, not
new local human annotation.

## Paper-safe wording

Use these formulations only when the corresponding evidence exists:

- "We trained K-6 using silver labels generated by the preceding system version
  (`risk > 50`). We do not use those labels for primary evaluation."
- "We evaluated K-6 on an external, held-out claim benchmark derived from
  published fact-checker verdicts; this is not an end-to-end evidence retrieval
  benchmark."
- "The end-to-end pipeline is evaluated on a separately frozen claim-evidence
  set; source records, predictions, and configuration hashes are archived."

Do not claim "human annotated", "double blind", a Fleiss kappa, a full-system
F1, or an ablation effect unless the corresponding archived data and executable
run establish it.
